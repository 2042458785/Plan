# 公司网站制作、Nginx 部署与域名配置

> 适用项目：`company-website`。
> 当前形态：纯静态公司展示网站，不需要 Node.js、数据库或后端服务。
> 推荐架构：域名 DNS -> 云服务器公网 IP -> Nginx -> 网站静态文件。
> 文档核对日期：2026-07-18。

## 1. 当前网站现状

项目位于仓库根目录的：

```text
company-website/
├── index.html
├── styles.css
├── script.js
└── assets/
```

当前页面包含公司简介、业务模式、商品方向、履约流程、运营系统和企业信息，适合作为第一版公司官网。

浏览器实际使用的图片为：

```text
assets/changwu-dao-hero-v2.jpg
assets/changwu-products-v2.jpg
assets/changwu-fulfillment-v2.jpg
```

`assets` 中其余 PNG 文件目前没有被网页引用，可以保留作设计源文件，但不是网站运行所必需。整个网站约 11 MB，直接由 Nginx 提供静态文件即可。

## 2. 上线前必须确认的内容

### 2.1 确定域名和商务邮箱

先完成：

1. [公司域名注册](01.公司域名注册.md)。
2. [公司邮箱创建](02.公司邮箱创建.md)。
3. 确认最终使用的主域名，例如 `YOUR_DOMAIN.com`。
4. 确认网站公开邮箱，例如 `support@YOUR_DOMAIN.com`。

当前网页的“商务联系”仍显示：

```text
企业域名与商务邮箱启用后公布
```

正式上线前，应在 `company-website/index.html` 中把它替换为实际商务邮箱，并使用可点击的邮件链接：

```html
<a href="mailto:support@YOUR_DOMAIN.com">support@YOUR_DOMAIN.com</a>
```

同时建议在 `<head>` 中增加正式域名对应的规范链接：

```html
<link rel="canonical" href="https://YOUR_DOMAIN.com/">
```

### 2.2 本地预览

不要直接双击 `index.html` 作为唯一测试方式。应在仓库根目录启动本地 HTTP 服务：

```bash
cd company-website
python3 -m http.server 8080
```

浏览器打开：

```text
http://127.0.0.1:8080
```

至少检查：

- 首页、图片、样式和滚动动画正常。
- 手机和电脑宽度下导航可用。
- 页面中没有测试文字、错误邮箱或未公开信息。
- 浏览器开发者工具的 Console 和 Network 中没有 404。
- 公司中文名、英文名和营业执照保持一致。

### 2.3 按当前结构继续制作网站

当前项目没有构建步骤，修改后保存并刷新浏览器即可看到结果。各文件分工如下：

| 文件 | 负责内容 | 修改原则 |
|---|---|---|
| `index.html` | 页面结构、标题、公司资料、业务文字和图片引用 | 保持语义化标签；公司信息与营业执照一致 |
| `styles.css` | 色彩、排版、响应式布局和动画外观 | 同时检查电脑、平板和手机宽度 |
| `script.js` | 菜单、滚动场景、商品切换和复制按钮 | 不在脚本中保存密码、密钥或个人资料 |
| `assets/` | 网站公开图片和图标 | 使用压缩后的 Web 图片，不放证件或内部资料 |

制作新内容时按以下顺序操作：

1. 先在 `index.html` 中增加内容结构和可访问文本。
2. 在 `styles.css` 中完成桌面和手机布局。
3. 只有确实需要交互时才修改 `script.js`。
4. 图片先压缩，再放入 `assets` 并使用有版本含义的英文文件名。
5. 本地预览并检查 404、控制台错误、键盘导航和手机显示。
6. 提交或备份稳定版本后再部署到服务器。

第一版官网建议保持展示站定位，不在静态页面中直接收集身份证、银行卡或其他敏感信息。如果后续增加联系表单、登录、订单或支付功能，就已经不是纯静态网站，应单独设计后端、数据存储、隐私说明、风控和备份方案，不能只靠当前 Nginx 静态配置。

## 3. 选择服务器地域

| 方案 | 是否需要 ICP 备案 | 更适合的场景 | 注意事项 |
|---|---|---|---|
| 中国内地云服务器 | 对外提供网站服务前通常需要完成 ICP 备案 | 主要访问者在中国内地 | 先备案，再解析和正式开放；备案信息需持续保持真实 |
| 中国香港、新加坡或其他境外服务器 | 通常不走中国内地 ICP 备案流程 | 海外客户为主、需要较快上线 | 中国内地访问速度和稳定性可能不如内地节点 |

当前业务面向英国等海外市场。如果官网主要用于海外客户和平台审核，可以优先评估中国香港或新加坡服务器；如果主要用于中国内地访问，则选择中国内地服务器并先完成 ICP 备案。

中国内地节点的具体备案要求以服务器接入商和工信部备案系统的实时提示为准。备案完成后，应按要求在网站底部展示备案号并链接至工信部备案系统。

## 4. 服务器准备

第一版静态站点可使用以下基础配置：

```text
操作系统：Ubuntu 24.04 LTS 或当前受支持的 Ubuntu LTS
CPU：1 核即可起步
内存：1 GB 即可起步
磁盘：20 GB 以上
网络：固定公网 IPv4
```

云平台安全组开放：

| 端口 | 用途 | 建议来源 |
|---|---|---|
| 22/TCP | SSH 管理 | 尽量只允许管理员固定 IP |
| 80/TCP | HTTP 和证书验证 | `0.0.0.0/0`、`::/0` |
| 443/TCP | HTTPS | `0.0.0.0/0`、`::/0` |

不要开放数据库端口，也不要使用弱密码登录 SSH。优先使用 SSH 密钥，并关闭不必要的云服务端口。

登录服务器：

```bash
ssh SSH_USER@SERVER_IP
```

安装 Nginx 和同步工具：

```bash
sudo apt update
sudo apt install -y nginx rsync
sudo systemctl enable --now nginx
sudo systemctl status nginx
```

先在浏览器访问 `http://SERVER_IP`，确认可以看到 Nginx 默认页面。若无法访问，优先检查云安全组、服务器防火墙、Nginx 状态和公网 IP，而不是反复修改网站文件。

## 5. 上传当前网站

### 5.1 从本地电脑上传

在本项目仓库根目录执行：

```bash
rsync -avz company-website/ SSH_USER@SERVER_IP:/tmp/changwu-site/
```

这里的结尾 `/` 很重要，表示上传 `company-website` 目录中的内容，而不是再嵌套一层同名目录。

### 5.2 在服务器放入正式目录

登录服务器后执行：

```bash
sudo install -d -m 0755 /var/www/changwu
sudo rsync -a /tmp/changwu-site/ /var/www/changwu/
sudo find /var/www/changwu -type d -exec chmod 755 {} \;
sudo find /var/www/changwu -type f -exec chmod 644 {} \;
```

检查入口文件：

```bash
ls -lah /var/www/changwu
test -f /var/www/changwu/index.html && echo "index.html 已就位"
```

不要把营业执照原图、身份证、银行资料、服务器私钥或 `.env` 文件放进 `/var/www/changwu`。这个目录中的文件原则上都可能被公网访问。

## 6. 配置 Nginx

以下配置适合当前纯静态单页网站。把其中两处 `YOUR_DOMAIN.com` 替换成真实域名。

创建配置文件：

```bash
sudo nano /etc/nginx/sites-available/changwu.conf
```

写入：

```nginx
server {
    listen 80;
    listen [::]:80;

    server_name YOUR_DOMAIN.com www.YOUR_DOMAIN.com;

    root /var/www/changwu;
    index index.html;

    access_log /var/log/nginx/changwu.access.log;
    error_log  /var/log/nginx/changwu.error.log;

    charset utf-8;

    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml;

    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header X-Frame-Options "SAMEORIGIN" always;

    location = /index.html {
        expires -1;
        try_files $uri =404;
    }

    location ~* \.(?:css|js)$ {
        expires 1h;
        try_files $uri =404;
    }

    location ~* \.(?:jpg|jpeg|png|webp|gif|svg|ico|woff|woff2)$ {
        expires 30d;
        try_files $uri =404;
    }

    location / {
        try_files $uri $uri/ =404;
    }

    location ~ /\.(?!well-known/) {
        deny all;
    }
}
```

当前网站使用页内锚点，不需要把所有不存在的路径回退到 `index.html`。因此这里使用 `=404`，能更早发现错误链接。如果未来改成 Vue、React 等前端路由应用，再将 `location /` 调整为：

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

启用配置并检查：

```bash
sudo ln -s /etc/nginx/sites-available/changwu.conf /etc/nginx/sites-enabled/changwu.conf
sudo nginx -t
sudo systemctl reload nginx
```

只有 `sudo nginx -t` 成功后才能 reload。不要跳过语法检查。

通过本机强制指定 Host 测试域名虚拟主机：

```bash
curl -I -H 'Host: YOUR_DOMAIN.com' http://127.0.0.1
```

预期看到 `HTTP/1.1 200 OK` 和 `Server: nginx`。

## 7. 配置域名 DNS

进入域名 DNS 控制台，为网站增加：

| 主机记录 | 类型 | 记录值 | 用途 |
|---|---|---|---|
| `@` | A | `SERVER_IP` | 根域名 `YOUR_DOMAIN.com` |
| `www` | A | `SERVER_IP` | `www.YOUR_DOMAIN.com` |

初次配置时 TTL 可以使用控制台默认值或较短值，例如 600 秒；稳定后再延长。

特别注意：

1. 网站的 A 记录和邮箱的 MX 记录可以共存。
2. 不要删除 `02.公司邮箱创建.md` 中已经配置的 MX、SPF、DKIM、DMARC 和邮箱相关 CNAME。
3. 不要添加 AAAA 记录，除非服务器已经正确配置公网 IPv6、Nginx 监听和防火墙。
4. 如果 DNS 使用了 CDN 或代理功能，首次申请证书前应确认 80/443 端口能正确回到该服务器。

在本地检查解析：

```bash
dig +short YOUR_DOMAIN.com A
dig +short www.YOUR_DOMAIN.com A
```

两个结果都应指向 `SERVER_IP`。随后测试：

```bash
curl -I http://YOUR_DOMAIN.com
curl -I http://www.YOUR_DOMAIN.com
```

## 8. 配置 HTTPS

必须先满足：

- 域名已经解析到当前服务器。
- 80 端口公网可访问。
- Nginx 配置测试通过。
- `http://YOUR_DOMAIN.com` 已经能打开网站。

Certbot 官方当前优先提供 Snap 安装方式。服务器支持 Snap 时执行：

```bash
sudo snap install --classic certbot
sudo ln -s /snap/bin/certbot /usr/local/bin/certbot
sudo certbot --nginx -d YOUR_DOMAIN.com -d www.YOUR_DOMAIN.com
```

在 Certbot 提示中选择把 HTTP 重定向到 HTTPS。完成后重新检查：

```bash
sudo nginx -t
sudo systemctl reload nginx
curl -I https://YOUR_DOMAIN.com
curl -I https://www.YOUR_DOMAIN.com
```

测试自动续期：

```bash
sudo certbot renew --dry-run
systemctl list-timers | grep certbot
```

不要手工复制或修改 `/etc/letsencrypt/live/` 中的证书文件。证书续期测试失败时，应先查看 Certbot 日志、DNS、80 端口和 Nginx 配置。

## 9. 中国内地服务器的备案衔接

如果服务器在中国内地：

1. 在服务器提供商的备案系统提交企业 ICP 备案。
2. 主办单位、负责人、证件和域名信息必须与真实材料一致。
3. 未完成备案前，不要把域名正式解析到内地服务器对外提供网站服务。
4. 备案成功后，根据接入商要求完成接入、解析和网站开放。
5. 在网站页脚展示备案号，并链接到：`https://beian.miit.gov.cn/`。
6. 上线后继续按照所在地及接入商提示处理公安联网备案等要求。

页脚示例：

```html
<a href="https://beian.miit.gov.cn/" rel="noopener noreferrer" target="_blank">
  蜀ICP备XXXXXXXX号-X
</a>
```

备案号必须使用审核通过后的真实号码，不要在审核前自行编造。

## 10. 日常更新网站

每次更新遵循：本地修改 -> 本地预览 -> 服务器备份 -> 上传 -> 验收。

### 10.1 本地上传到临时目录

```bash
rsync -avz company-website/ SSH_USER@SERVER_IP:/tmp/changwu-site-next/
```

### 10.2 服务器备份并发布

先为备份文件填写真实时间，例如 `20260718-1530`：

```bash
sudo install -d -m 0700 /var/backups/changwu
sudo tar -C /var/www -czf /var/backups/changwu/changwu-20260718-1530.tar.gz changwu
sudo rsync -a --delete /tmp/changwu-site-next/ /var/www/changwu/
sudo nginx -t
sudo systemctl reload nginx
```

`--delete` 会删除服务器目录中本地新版不存在的文件，因此必须确认目标固定为 `/var/www/changwu/`，不能对 `/var/www/` 或其他宽泛目录执行。

### 10.3 回滚

如果新版本有问题：

```bash
sudo install -d -m 0755 /tmp/changwu-rollback
sudo tar -C /tmp/changwu-rollback -xzf /var/backups/changwu/changwu-20260718-1530.tar.gz
sudo rsync -a --delete /tmp/changwu-rollback/changwu/ /var/www/changwu/
sudo nginx -t
sudo systemctl reload nginx
```

确认回滚成功后，再人工清理临时目录。不要在不确定路径时执行递归删除命令。

## 11. 安全和维护

每月至少检查一次：

```bash
sudo apt update
apt list --upgradable
sudo systemctl status nginx
sudo nginx -t
sudo certbot certificates
df -h
```

查看错误日志：

```bash
sudo tail -n 100 /var/log/nginx/changwu.error.log
sudo tail -n 100 /var/log/nginx/changwu.access.log
```

长期规则：

- 域名、云服务器和企业邮箱的管理员账号开启双重验证。
- SSH 私钥、云平台密钥和证书私钥不通过微信或邮件明文发送。
- 只把网站公开文件放进 `/var/www/changwu`。
- 系统安全更新、Nginx 状态、证书续期和磁盘空间需要持续检查。
- 页面内容发生公司名称、地址、业务或联系方式变化时同步更新。
- 上线前和重大更新后分别保留一份可恢复备份。

## 12. 常见故障

### IP 能访问，域名不能访问

检查：

1. A 记录是否指向正确公网 IP。
2. DNS 是否尚未生效。
3. `server_name` 是否写错。
4. 如果使用中国内地服务器，备案或接入是否阻断。

### 首页能打开，图片或样式丢失

检查：

```bash
ls -lah /var/www/changwu
ls -lah /var/www/changwu/assets
sudo tail -n 100 /var/log/nginx/changwu.error.log
```

确认 HTML 中的相对路径、文件名大小写和服务器文件完全一致。Linux 区分大小写。

### Certbot 申请证书失败

检查：

- 根域名和 `www` 是否都解析到当前服务器。
- 80 端口是否开放。
- Nginx 是否运行。
- CDN 或代理是否拦截证书验证。
- 域名是否刚修改 DNS，仍在传播中。

### 更新后仍看到旧页面

先检查服务器文件是否已经更新，再使用浏览器无痕窗口或强制刷新。图片缓存最长设置为 30 天；如果替换图片内容，建议同时修改文件名并更新 HTML 引用，例如从 `hero-v2.jpg` 改成 `hero-v3.jpg`。
