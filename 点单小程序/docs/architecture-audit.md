# 工程一致性与置信度审查（2026-11-03）

## 审查范围

依据本聊天的原始要求及用户后续纠正，核对参考工程实际源码、当前实现、编译与行为测试。之前“做完”“按照原项目技术栈”的说法，不能证明工程结构、数据库结构和安全隔离满足要求；用户继续提问也不表示接受旧实现。

## 初始核查结论

旧实现不满足完整工程对齐要求（高置信度，直接源码证据）：

| 项目 | 参考工程证据 | 旧实现问题 | 本次验收标准 |
|---|---|---|---|
| 入口与分层 | 参考后端的 main.go → src/cmd → app/router → api/http_controller → service → dao/model | main.go 内联路由与存储 | 独立分层，启动入口精简 |
| 配置 | 参考后端的 src/config/config.go 与 config.yaml，支持 config.local.yaml | 环境变量为主，无 YAML | YAML 加载、校验、覆盖实际生效 |
| 数据库 | config/mysql.go，GORM，sys_ 前缀、单数表名、连接池与 AutoMigrate | JSON 文件 / 单行 snapshots | MySQL 业务分表，真实事务与回归测试 |
| 日志和认证 | global.Logger（Zap），Bearer JWT，中间件鉴权 | slog，内存 Cookie 会话 | Zap、JWT、可撤销持久化会话、服务端判权 |
| 顾客前端 | 参考顾客端的 package.json、main.ts、config.ts、router/store/api | 单一 App.vue，无 Router/Vuex/Axios 分层 | Vue3/TS、Router/Vuex、配置与请求层 |
| 构建工具 | 参考顾客端的 serve 明确为 vite；管理端 serve 为 vue-cli-service serve | 将后台也编入 Vite 顾客包 | 分别沿用原项目两套实际工具链 |
| 管理端 | 参考管理端：Vue2 + Vue CLI + Element UI + Router + Vuex | Vue3 组件与顾客端混编 | 独立 admin 工程、端口和产物 |
| 入口隔离 | 两个独立前端 | 顾客页有后台入口和后台组件 | 顾客包无后台组件/入口，后台独立部署，API 强制判权 |

安全判断：隐藏后台入口本身不构成鉴权。需要同时验证“无令牌、伪造令牌、过期/撤销令牌、错误角色不能调用管理接口”，以及顾客产物不包含后台实现。

## 可复核的事实与边界

- 顾客端参考项目确实使用 Vite；删除 Vite 并不能证明忠实于原工程。应按源码区分顾客端和管理端。
- 商城业务不应复制扑克玩法、链上转账、GPS、游戏 WebSocket 等业务代码；保留参考工程的配置、分层、依赖注入、数据访问、日志、认证与前端组织方式。
- 参考库内容不属于商城；只能使用新建的独立库验证，不能迁移或改写扑克业务表。
- 置信度只对应具体检查；构建通过不能替代 MySQL 集成、权限与浏览器验证。最终结果在本文件后续记录，不使用“世界最好”或“完全相同”的无依据表述。
